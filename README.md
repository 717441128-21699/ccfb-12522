# 终点摄影判读系统

基层田径比赛的低成本终点摄影方案:用一台 240fps 运动相机代替终点摄影机,
把视频处理成终点线扫描图(photo-finish strip),在网页上判读名次与成绩。

纯前端实现(Vite + TypeScript),视频不解压到服务器,全部在浏览器内完成。

## 运行

```bash
npm install
npm run dev      # 开发
npm run build    # 构建(含类型检查)
npm test         # 合成视频验证
```

需要支持 WebCodecs 的浏览器(Chrome / Edge)。视频支持 mp4/mov(H.264、HEVC)。

## 工作流程(对应五个页面)

1. **赛事** — 新建赛事,按道次录入选手,上传比赛视频(自动读出帧率/帧数)。
2. **终点线标定** — 抽取任意一帧,在画面上拖两个点标出终点线;相机架歪了
   就把线拉斜,采样沿斜线进行(双线性插值)。同页从音轨自动检测发令枪声
   作为计时零点,也可手动输入。
3. **扫描成像** — 逐帧解码,每帧只取终点线那一列像素,拼成扫描图:
   横轴 = 时间(1 列 = 1 帧,240fps 下 1 像素 ≈ 4.17ms),纵轴 = 沿终点线的位置。
   长视频可只扫冲线附近的帧范围。
4. **判读** — 竖线跟随鼠标,读数精确到千分之一秒;选中道次后单击标注冲线
   (以躯干前沿为准);几乎同时撞线时横向拖框局部放大,可开关插帧(列间插值)
   平滑比较,放大视图中点击可到亚帧精度。
5. **成绩公告** — 自动排名;短跑手录风速,顺风超过 +2.0 m/s 的成绩标注
   "风速超规,不计纪录";一键生成 PDF 成绩单,内含带时间刻度的扫描图存档。

## 计时原理

- 帧 `i` 的视频内时刻 = `i / fps`(fps 取样本时长中位数,对变帧率稳)。
- 比赛用时 = 冲线帧时刻 − 发令枪零点(音轨中能量突变的上升沿)。
- 读数分辨率 = 1 帧;240fps 下为 1/240 s ≈ 4.17ms,远优于手计的 0.1s。

## 验证

`npm test` 用**带已知冲线时刻的合成视频**跑完整条流水线
(逐帧采样终点线 → 拼扫描图 → 检测冲线 → 换算成绩),
断言每个道次的读数误差 ≤ 1 帧时长;另覆盖斜线采样、发令枪检测
(合成音轨,误差 < 10ms)与时间格式化。见 `tests/verification.test.ts`。
